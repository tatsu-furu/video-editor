# 設計判断の記録

設計書と異なる判断や、設計書に書かれていない判断を、新しいものを上に記録する。

| 日付       | 判断                                                                                                                                                                                      | 理由                                                                                                                                                                                   |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-10-03 | `Project` に `markers?: Marker[]`（ピン・目印）を追加。ソース時刻で持つ。タイムラインのクリックはクリップの「チェック」の付け外しにし、チェックしたクリップをまとめて削除できるようにした | ピンはカットしても同じ場面に付いたまま動くように字幕と同じ持ち方にした。古い保存データに無くても動くよう省略可能にした。分割した片方だけを消す操作を分かりやすくするため               |
| 2026-10-03 | 書き出しの映像コーデックは H.264 を優先し、使えない環境では VP9 → AV1 の順に切り替える（MP4 のまま）。音声は AAC → Opus                                                                   | Linux 版 Chromium などは H.264 / AAC のエンコーダーを持たない。止めるより書き出せるほうがよいので、切り替えたことを完了時に表示する                                                    |
| 2026-10-03 | 文字起こしは「発話区間を 28 秒以下の窓に分け、窓の終わり 6 秒以内でいちばん静かな位置で区切る」方式にした（設計書の「30 秒チャンク・5 秒オーバーラップ」ではない）                        | 窓ごとに進捗表示・キャンセル・キャッシュができ、オーバーラップの重複除去も要らない。言葉の途中で切らないよう静かな位置で区切る                                                         |
| 2026-10-03 | 単語単位のタイムスタンプは使わず、セグメント単位で扱う（字幕の分割時刻は文字数で按分）                                                                                                    | 単語タイムスタンプ付きの Whisper（cross-attention 出力つき）の ONNX モデルが少なく、速度も落ちるため。`TranscriptSegment.words` と分割ロジックは対応済みなので、モデルを替えれば使える |
| 2026-10-03 | Silero VAD が読み込めない（オフラインなど）ときは、エンベロープから作った疑似確率で発話区間を出す                                                                                         | 解析そのものを止めないため。どちらを使ったかは素材一覧に表示する                                                                                                                       |
| 2026-10-03 | Undo/Redo は Immer の produceWithPatches。編集操作は「draft を書き換えるレシピ」として `core/project/ops.ts` に書き、`pure()` で包んだ純粋関数をテストする                                | 設計書の「core の純粋関数」と「Immer の patches で履歴」を両立させるため。core は Immer に依存するが、Immer は Worker でも使えるライブラリなので依存の向きは保たれる                   |
| 2026-10-03 | ドラッグ操作（トリム・字幕の移動）は途中経過を履歴に残さず、離したときに 1 件だけ残す                                                                                                     | ドラッグ中の細かい変更で履歴が埋まらないようにするため                                                                                                                                 |
| 2026-10-03 | プレビューの描画は requestAnimationFrame のループで行う（requestVideoFrameCallback は使っていない）                                                                                       | 2 つの video 要素の切り替えと逆再生（シークで代用）を同じループで扱えるため。フレーム落ちは getVideoPlaybackQuality で検知する                                                         |
| 2026-10-03 | J（逆再生）は video 要素の負の再生速度が使えないため、シークを繰り返して代用する。逆再生中は音を出さない                                                                                  | ブラウザの制約                                                                                                                                                                         |
| 2026-10-03 | 解析の 16kHz PCM から 100ms ごとの K 特性ブロックを作っておき、「残っている区間の元音声のラウドネス」はそこから計算する（モノラルなのでステレオ相当に +3 LU）                             | 元音声を 48kHz でデコードし直さずに、カットのたびにすぐ計算できるため。最終的な −14 LUFS への正規化は書き出し時に 48kHz ステレオで測り直す                                             |
| 2026-10-03 | トゥルーピークはサンプルピークで近似し、リミッターの上限を −1.5 dBFS（目標 −1 dBTP から 0.5 dB の余裕）にした                                                                             | 4 倍オーバーサンプリングの真のピーク計測を省くため。ffmpeg の ebur128 で −1 dBTP 以下を確認済み                                                                                        |
| 2026-10-03 | 字幕フォントは @fontsource/noto-sans-jp の woff2（unicode-range ごとに分割）を自前で配信し、使う文字の分だけ読み込む                                                                      | COEP のため外部 CDN は使えない。日本語フォントは1ファイルが大きいので、分割版を使う                                                                                                    |
| 2026-10-03 | リポジトリ直下に Vite のプロジェクトを置く（`video-editor/` サブフォルダをやめた）                                                                                                        | Netlify と GitHub Actions がそのまま動くようにするため                                                                                                                                 |
| 2026-10-03 | Linter は ESLint ではなく oxlint を使う                                                                                                                                                   | Vite 公式テンプレート（create-vite 9）の既定が oxlint で、高速かつ設定が少ないため。不足が出たら ESLint を追加する                                                                     |
| 2026-10-03 | 単体テストは Vitest の node 環境で実行する                                                                                                                                                | P0 時点では DOM に依存するテストがない。`src/core/` は DOM 非依存を守る。DOM が必要になったテストだけ jsdom などを個別に指定する                                                       |
