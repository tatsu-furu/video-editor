# ブラウザ動画編集アプリ 設計書

## 1. 概要とコンセプト

ブラウザだけで動く、初心者向けの動画編集Webアプリを作る。サーバー処理・APIキー・LLMは使わず、すべての処理をユーザーのPC上（ブラウザ内）で行う。静的ファイルとして自前ドメインで公開する。

### 想定ユースケース

1. **ゲーム録画のハイライト動画**（主目的）：30分〜2時間程度の録画から盛り上がった場面を残し、不要部分を削って、字幕とBGMを付けて5〜20分程度の動画にする。
2. **トーク・解説動画**：無音や間を自動で詰め、文字起こしから字幕を付け、BGMを声に合わせて自動で下げる。

### 設計の原則

- **自動処理は「提案」**：自動カット・字幕・音量調整の結果は、動画を直接加工せずタイムライン上の編集データとして載せる。ユーザーはいつでも手で直せる（非破壊編集）。
- **一般的な編集ソフトと同じ操作感**：タイムライン、再生ヘッド、分割、リップル削除、Undo/Redo、定番のキーボードショートカットを備える。
- **できることを絞る**：トラックは「映像（＋元音声）1・BGM 1・字幕 1」に固定。エフェクト、トランジション、画像テロップ、複数レイヤーはMVPでは持たない。
- **プライバシー**：動画はどこにもアップロードしない。外部通信は音声認識モデルの初回ダウンロードのみ。

## 2. スコープ

MVPは「読み込み → 自動カット候補 → 手動で削る → 文字起こし → ワンボタン字幕 → BGMと音量調整 → MP4書き出し」の一本道を完成させることに絞る。

| 区分          | 機能                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| MVPに含む     | 複数動画ファイルの読み込みと連結、プレビュー再生、分割・削除・トリム・並べ替え、Undo/Redo               |
| MVPに含む     | 音声解析による自動カット候補（トーク用の無音検出、ゲーム用の盛り上がり検出）と一括適用                  |
| MVPに含む     | ブラウザ内Whisperでの日本語文字起こし、文字起こし結果の確認・修正、ワンボタン字幕生成、字幕スタイル設定 |
| MVPに含む     | BGMの挿入（ループ・フェード）、声に合わせた自動ダッキング、ラウドネス正規化、BGM音量スライダー          |
| MVPに含む     | MP4書き出し（字幕焼き込み）、SRT書き出し、プロジェクトの自動保存と再開                                  |
| MVPに含まない | LLM連携、読み上げ音声（VOICEVOX）、映像のシーン検出、フィラー語の自動カット、テキスト編集でのカット     |
| MVPに含まない | 画像・図形テロップ、トランジション、エフェクト、色補正、複数映像レイヤー、縦動画テンプレート            |
| MVPに含まない | スマホ・タブレット対応、デスクトップアプリ版、ユーザーアカウント、クラウド保存                          |

未決事項：アプリ名、出力の主対象（YouTube横動画のみか、ショート縦動画も視野に入れるか）。

## 3. 技術スタックと動作環境

Vite + React + TypeScript の静的SPAとし、重い処理はすべてWeb Workerで行う。以下のライブラリ名は選定方針であり、API名や使い方は実装時に必ず最新の公式ドキュメントで確認すること。

| 領域           | 採用技術                                                   | 用途                                                                |
| -------------- | ---------------------------------------------------------- | ------------------------------------------------------------------- |
| ビルド・UI     | Vite、React、TypeScript（strict）                          | SPA本体                                                             |
| 状態管理       | Zustand + Immer                                            | プロジェクト状態、Undo/Redo（Immerのpatchesで履歴）                 |
| メディア入出力 | Mediabunny（WebCodecsベース）                              | コンテナの読み取り、映像・音声のデコード／エンコード、MP4への多重化 |
| 音声処理       | Web Audio API、自前DSP（Worker内）                         | プレビューのミキシング、エンベロープ、LUFS、ダッキング、リミッター  |
| 音声区間検出   | Silero VAD（onnxruntime-web）                              | 発話区間の検出                                                      |
| 音声認識       | Transformers.js（Whisper、WebGPU優先・WASMフォールバック） | 日本語文字起こし                                                    |
| Worker間通信   | Comlink                                                    | Workerの関数呼び出しを型付きで扱う                                  |
| 永続化         | IndexedDB（idb）、OPFS                                     | プロジェクトJSON、ファイルハンドル、解析キャッシュ、PCM             |
| フォント       | Noto Sans JP（woff2を自前ホスト）                          | 字幕描画（プレビューと書き出しで同一フォント）                      |
| テスト         | Vitest、Playwright                                         | ロジックの単体テスト、E2Eスモークテスト                             |

### 対象ブラウザ

- 必須：デスクトップ版 Chrome / Edge の最新版（WebCodecs、WebGPU、File System Access API、OPFSを使うため）。
- それ以外（Safari、Firefox）：起動時に機能チェックを行い、不足があれば警告を出す。動作保証はしない。
- スマホ・タブレット：対象外。

### ホスティング要件

静的ファイル配信のみ。ただしonnxruntime-webのマルチスレッドWASMなどでSharedArrayBufferを使うため、全レスポンスに以下のヘッダーを付ける。

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

- 開発サーバー（Vite）にも同じヘッダーを設定する。
- 起動時に `crossOriginIsolated` が true であることを確認し、false ならWASMをシングルスレッドで動かす。
- 音声認識モデルは既定でHugging Faceから取得する。将来、自前ドメインへの配置にも切り替えられるよう、モデル取得元のURLは設定値にしておく。

COEPを有効にすると、CORSに対応していない外部リソース（画像、フォント、埋め込み）は読み込めなくなる。外部素材は原則として自前ホストし、将来どうしても必要になった場合は `Cross-Origin-Embedder-Policy: credentialless` への切り替えを検討する。

## 4. アーキテクチャ

メインスレッドは「プロジェクトJSONの編集と表示」だけを担い、デコード・解析・音声認識・書き出しは3つのWorkerに分ける。自動処理の結果は必ずプロジェクト状態を通して反映し、UIやWorkerが独自にタイムラインを持たない。

構成は次の3層。

- **メインスレッド**：UI（React。画面・タイムライン操作・ショートカット・各パネル） → プロジェクト状態（Zustand + `core/` の純粋関数、Undo/Redo、自動保存） → プレビュー（video要素×2 + Canvas、Web Audioでミックス）
- **Web Worker**（メインスレッドからComlinkで処理を依頼し、進捗と結果を受け取る）：`analysis.worker`（エンベロープ・VAD・盛り上がり検出・LUFS）、`asr.worker`（Whisper／WebGPU、残った区間だけ文字起こし）、`export.worker`（デコード・字幕合成・エンコード・MP4書き出し）
- **ブラウザ内の保存先とファイル**（WorkerからPCM・キャッシュの読み書き、素材と出力ファイルへのアクセス）：IndexedDB（プロジェクトJSON、ファイルハンドル）、OPFS（16kHz PCM、解析・文字起こしキャッシュ）、ローカルファイル（元動画は読み取りのみ、書き出し先のMP4・SRT）

字幕の描画関数（`render/subtitles.ts`）はプレビューとexport.workerで共有し、見た目を一致させる。プロジェクトの自動保存はメインスレッドから直接IndexedDBに書く。

### ディレクトリ構成

```

  ui/

    preview/        プレビュー表示と再生コントロール
    timeline/       Canvas描画のタイムラインと操作ハンドラ
    panels/         素材、自動カット候補、文字起こし、字幕スタイル、BGM、書き出し
  core/             型定義と純粋関数（DOMに依存しない）
    project/        Project型、編集操作、Undo/Redo
```

### 依存の向き

- `core/` は何にも依存しない（WorkerからもUIからもimportできる）。
- `ui/` は `store/` と `playback/` だけを通じて状態に触れる。`workers/` を直接呼ばない。
- `workers/` は `core/`、`media/`、`render/`、`storage/` を使う。Reactには依存しない。

## 5. データモデル

プロジェクトは1つのJSONで表し、編集はすべてこのJSONへの純粋関数として実装する。設計上の要点は次の3つ。

- **映像トラックはマグネティック**：クリップは隙間なく順に並び、タイムライン上の位置は保存せず「前のクリップの長さの合計」から導出する。削除すると後ろが自動で詰まる。
- **字幕と文字起こしは元動画の時刻（ソース時刻）で保持**：カットしても字幕を動かす処理が不要になる。カットされた区間の字幕は自動で非表示、一部だけ残れば表示区間も切り詰める。
- **ダッキングの音量カーブは保存しない**：発話区間（ソース時刻）から毎回導出する。カット後も常に整合する。

### 型定義（案）

型定義は `src/core/project/types.ts` に実装済み。変更した場合は `docs/DECISIONS.md` に記録する。

```ts
type Id = string // nanoid
type Sec = number // 秒（浮動小数）
type Db = number // デシベル

interface Project {
  version: 1
  id: Id
  name: string
  createdAt: string // ISO 8601
  updatedAt: string
  mode: 'game' | 'talk' // 自動カットの既定モード
  output: { width: number; height: number; fps: number; sampleRate: 48000 }
  assets: Record<Id, Asset>
  videoTrack: VideoClip[] // 並び順 = 再生順
  bgmTrack: BgmClip[] // 重なりなし、timelineStart 昇順
  subtitles: SubtitleItem[]
  subtitleStyle: SubtitleStyle
  audioMix: AudioMix
  suggestions: Suggestion[] // 自動カット候補
}

interface Asset {
  id: Id
  kind: 'video' | 'audio'
  name: string
  duration: Sec
  fingerprint: { name: string; size: number; lastModified: number; headHash: string } // 先頭1MBのSHA-256
  handleKey?: string // IndexedDBに保存したFileSystemFileHandleのキー
  video?: { width: number; height: number; fps: number; codec: string }
  audioTracks: { index: number; label: string; channels: number; sampleRate: number }[]
  analysisAudioTrack: number // 解析に使う音声トラック（OBSのマイク別録り用）
}

interface VideoClip {
  id: Id
  assetId: Id
  sourceIn: Sec
  sourceOut: Sec
  gainDb: Db // 元音声の音量（既定 0）
  muted: boolean
}

interface BgmClip {
  id: Id
  assetId: Id
  timelineStart: Sec
  timelineEnd: Sec
  sourceOffset: Sec // BGMファイル内の再生開始位置
  loop: boolean
  fadeIn: Sec // 既定 1.0
  fadeOut: Sec // 既定 2.0
}

interface SubtitleItem {
  id: Id
  assetId: Id // どの動画の音声に対応するか
  sourceStart: Sec
  sourceEnd: Sec
  text: string // 改行は \n
}

interface SubtitleStyle {
  fontFamily: 'Noto Sans JP'
  fontWeight: 400 | 700 | 900
  sizeRatio: number // 出力の高さに対する文字の大きさ（既定 0.055）
  color: string
  outlineColor: string
  outlineRatio: number // 文字サイズに対する縁取り幅（既定 0.12）
  position: 'bottom' | 'top'
  marginRatio: number // 端からの余白（既定 0.06）
  box: boolean // 半透明の背景帯
  maxCharsPerLine: number // 既定 18
  maxLines: 1 | 2 // 既定 2
}

interface AudioMix {
  preset: 'talk' | 'gameCommentary' | 'bgmForward'
  bgmOffsetDb: Db // UIの「BGMの大きさ」スライダー（-10〜+10）
  ducking: { enabled: boolean; amountDb: Db; attackMs: number; holdMs: number; releaseMs: number }
  targetLufs: number // 既定 -14
  truePeakDb: Db // 既定 -1
}

interface Suggestion {
  id: Id
  kind: 'silence' | 'lowActivity' | 'highlight'
  assetId: Id
  sourceStart: Sec
  sourceEnd: Sec
  score: number // 0〜1
  status: 'pending' | 'accepted' | 'rejected'
}
```

### 解析キャッシュ（プロジェクトJSONとは別に保存）

- `envelope`：音量エンベロープ（20ms刻みのdBFS、Float32Array）。
- `vad`：発話確率列と、確定済みの発話区間リスト。
- `transcript`：`{ start, end, text, words?: { start, end, text, prob }[] }[]` とモデル名・言語。
- `pcm16k`：16kHzモノラルInt16のPCM（OPFSにファイルで保存。VADと音声認識で再利用）。
- キーは `asset.fingerprint` から作り、同じファイルを再度読み込んだときは再解析しない。

### 編集操作（すべて `core/` の純粋関数、単体テスト必須）

| 関数                                                                     | 内容                                                                 |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| `splitAt(project, t)`                                                    | タイムライン時刻 t でクリップを2つに分ける                           |
| `rippleDelete(project, t0, t1)`                                          | タイムライン区間を削除し後ろを詰める（複数クリップにまたがってよい） |
| `deleteClip(project, clipId)`                                            | クリップ単位の削除                                                   |
| `trimClip(project, clipId, edge, newSourceTime)`                         | クリップの開始・終了をトリム（ソース範囲を超えない）                 |
| `moveClip(project, clipId, newIndex)`                                    | クリップの並べ替え                                                   |
| `applySuggestions(project, ids)`                                         | 削除候補をまとめてカットに反映し、statusを accepted にする           |
| `generateSubtitles(project, assetId, transcript)`                        | 文字起こしから字幕を生成（既存の自動生成字幕は置き換え）             |
| `timelineToSource(project, t)` / `sourceToTimeline(project, assetId, s)` | 時刻の相互変換。カット済みのソース時刻は null を返す                 |

Undo/Redoは各操作をImmerの `produceWithPatches` で実行し、履歴を最大200件保持する。字幕テキストの連続入力は1秒以内なら1件にまとめる。

## 6. 読み込み・プレビュー・タイムライン編集

動画ファイルは丸ごとメモリに載せず、Fileオブジェクトから必要な範囲だけを読む。プレビューはvideo要素2つの交互再生で、カット境界でもなるべく途切れないようにする。

### 6.1 読み込み

1. ドラッグ＆ドロップ、またはファイル選択（`showOpenFilePicker`、非対応時は `<input type=file>`）。
2. Mediabunnyでコンテナを読み、長さ・解像度・fps・コーデック・音声トラック一覧を取得する。デコードできないコーデックはこの時点でエラーを出す。
3. Assetを作り、ファイルハンドルをIndexedDBに保存する。先頭1MBのSHA-256を計算してfingerprintにする。
4. 映像トラックの末尾にソース全体のクリップを1つ追加する。
5. バックグラウンドで音声解析（7章）を開始し、進捗をヘッダーに表示する。解析中も編集は可能。

- 対応コンテナ：MP4、MOV、MKV、WebM。OBSの録画形式を最優先で確認する。
- 音声トラックが複数ある場合（OBSでマイクとゲーム音を別トラックで録った場合など）、解析に使うトラックをユーザーが選べる。書き出しの音声は全トラックをミックスする。
- 2本目以降の動画は解像度やfpsが異なってもよい。出力設定は1本目に合わせ、異なる素材はレターボックスで収める。

### 6.2 プレビュー

- video要素を2つ用意し、片方で現在のクリップを再生、もう片方は次のクリップの `sourceIn` に事前シークして待機させる。境界で表示を切り替える。
- 表示はCanvasに描画する。`requestVideoFrameCallback` で映像フレームを描き、その上に字幕を重ねる。字幕の描画関数は書き出しと共通にする（10章）。
- 音声は各video要素を `MediaElementAudioSourceNode` でWeb Audioに通し、クリップごとのゲインを掛ける。BGMは別系統で再生し、ダッキングのカーブを `AudioParam` にスケジュールする（9章）。
- 再生ヘッドの時刻はタイムライン時刻で管理し、`timelineToSource` で各video要素の時刻に変換する。
- プレビュー解像度は「自動 / フル / 1/2」から選べる（既定は自動）。自動では、フレーム落ちが連続して検知されたら1/2に下げ、再生を止めたときに元へ戻す。

### 6.3 タイムライン

- 上から「字幕」「映像（波形付き）」「BGM（ダッキングカーブ付き）」の3トラック固定。
- 映像クリップにはサムネイル（間引き）と音声波形を表示する。波形は解析済みエンベロープから描く。
- 自動カット候補は映像トラック上に色付きの帯で重ねる（削除候補は赤の斜線、ハイライトは緑）。
- ズームは「全体表示」から「1フレーム単位」まで。描画はCanvasで行い、500クリップでも60fpsでスクロールできること。
- 操作：クリックで再生ヘッド移動、クリップ選択、端のドラッグでトリム、クリップのドラッグで並べ替え、範囲選択（I/O点またはドラッグ）。
- スナップ：再生ヘッド・クリップ境界・字幕境界に吸着する（Shiftを押している間は無効）。

## 7. 自動カット（音声解析と候補生成）

自動カットは「候補を出す」までを担い、適用はユーザーの操作で行う。トーク動画は発話の有無で、ゲーム録画は音量の盛り上がりで候補を作る。パラメータの数値はすべて初期値で、実素材で調整する前提とする。

### 7.1 前処理（全モード共通、analysis.workerで実行）

1. 解析対象の音声トラックを、Mediabunnyでチャンク単位にデコードする（全体をメモリに載せない）。
2. モノラル化し16kHzにリサンプルして、Int16でOPFSに書き出す（`pcm16k`）。
3. 同時に20msごとのRMS（窓40ms）をdBFSで計算し `envelope` に保存する。2時間でも約36万サンプルで済む。
4. 短期ラウドネス（窓400ms）と、その30秒移動中央値（ベースライン）も計算しておく。

### 7.2 発話区間検出（VAD）

- Silero VADを16kHz・512サンプル（32ms）単位で実行し、発話確率を得る。
- ヒステリシスで二値化する：確率0.5以上で発話開始、0.35未満で発話終了。
- 0.3秒未満の発話の切れ目は埋め、0.25秒未満の孤立した発話は捨てる。
- 結果は字幕の補正（8章）とダッキング（9章）でも使う。

### 7.3 トークモード：無音カット

- 発話のない区間が `minSilence`（既定0.6秒）以上続けば削除候補 `silence` にする。
- 発話の前後には `padding`（既定0.15秒）を残す。
- 境界は、前後0.3秒以内のエンベロープ極小点に吸着させる（音の途中で切らないため）。
- UIの「詰め具合」スライダーで `minSilence` を0.3〜2.0秒の範囲で変える。

### 7.4 ゲームモード：盛り上がり検出

ゲーム音は常に鳴っているため、無音ではなく「普段より大きい瞬間」を探す。

1. 興奮度 `e(t) = 短期ラウドネス(t) − ベースライン(t)`（dB）を計算する。
2. `e(t)` が閾値（既定 +6dB、「感度」スライダーで +3〜+12dB）を超える極大点をピークとし、ピーク同士は5秒以上離す。
3. マイク音声トラックを解析に選んでいる場合は、VADで発話中かつ声の大きさが中央値+6dB以上の区間（叫び・笑い）にも高いスコアを付ける。
4. 各ピークの前8秒・後4秒をハイライト区間 `highlight` とし、3秒未満の隙間で隣り合う区間は結合する。1区間は最長60秒。
5. スコアは区間内の `e(t)` の最大値を0〜1に正規化したもの。
6. ハイライト以外の区間を削除候補 `lowActivity` にする。
7. 「目標の長さ」（例：10分）を指定すると、スコアの高いハイライトから合計がその長さになるまで採用し、残りも削除候補にする。

### 7.5 候補の確認と適用

- 左パネルに候補の一覧を出す（サムネイル、長さ、スコア、種類）。クリックで候補の2秒前から再生する。
- 操作は「すべて適用」「この候補を残す（rejected）」「この候補を削除（accepted）」。
- キーボードで候補間を移動できる（N：次の候補、Shift+N：前の候補、Enter：適用、Backspace：却下）。
- 適用は `applySuggestions` 1回＝Undo1回分とする。
- パラメータを変えて再計算したら、未処理（pending）の候補だけを置き換える。

## 8. 文字起こしと字幕

文字起こしは既定で「カット後に残っている区間」だけを対象にする。2時間の録画全体をブラウザ内Whisperで処理すると時間がかかりすぎるため、先に削ってから文字起こしする流れを標準とする。

### 8.1 文字起こし（asr.workerで実行）

- 対象：「残っている区間のみ」（既定）または「素材全体」。
- 入力：`pcm16k` から対象区間を切り出す。VADで発話のない区間は送らない。
- モデルは3段階から選ぶ。初回はダウンロードサイズを表示して確認を取る。

| 選択肢       | モデル（候補）                   | 想定                 |
| ------------ | -------------------------------- | -------------------- |
| 高速         | Whisper base                     | 下書き用、精度は低め |
| 標準（既定） | Whisper small                    | 速度と精度のバランス |
| 高精度       | Whisper large-v3-turbo（量子化） | 精度重視、GPU必須    |

- 言語は日本語固定（`language: 'ja'`）。30秒チャンク・5秒オーバーラップで処理する。
- 単語単位のタイムスタンプが取れるモデル版を優先し、取れない場合はセグメント単位で扱う。
- WebGPUが使えない場合はWASMにフォールバックし、「かなり遅くなる」と警告する。
- 進捗（処理済み秒数／全体）と残り時間の目安を表示し、途中でキャンセルできる。
- 結果はソース時刻で `transcript` に保存し、同じ区間・同じモデルなら再利用する。

### 8.2 誤認識（ハルシネーション）対策

- VADの発話率が10%未満のセグメントは捨てる。
- 同じフレーズが3回以上連続するセグメントは捨てる。
- 「ご視聴ありがとうございました」など、無音区間で出やすい定型句を除外リストで弾く（リストは設定ファイルで管理）。

### 8.3 文字起こしパネル

- セグメントを時刻付きのリストで表示し、テキストをその場で編集できる。
- クリックでその位置へジャンプ。再生中は該当セグメントをハイライトする。
- 各セグメントに「この部分をカット」ボタン（セグメントの区間を `rippleDelete`）。
- カットされた区間のセグメントはグレー表示にする。

### 8.4 ワンボタン字幕生成

「字幕を入れる」ボタンで、現在の文字起こしから字幕トラックを作る。分割ルールは以下。

1. 句点・感嘆符・疑問符（。！？）で区切る。
2. 1行 `maxCharsPerLine`（既定18文字）×最大2行に収まらない場合は、読点（、）で区切る。それでも長ければ単語境界で区切る。
3. 単語タイムスタンプがあれば区切り位置から時刻を決め、なければ文字数で按分する。
4. 表示時間は最短0.8秒・最長6秒。次の字幕までの隙間が0.2秒未満なら詰める。
5. 末尾の句点は表示しない（設定でオン／オフ）。
6. 1秒あたり8文字を超える字幕は警告マークを付ける（直さなくてもよい）。

### 8.5 字幕の手動編集

- 字幕トラック上で、ドラッグで移動、端のドラッグで表示時間の変更。
- ダブルクリックでテキスト編集。分割（再生ヘッド位置）と、隣との結合。
- 字幕のない場所でダブルクリックすると空の字幕を追加する。
- スタイル（`SubtitleStyle`）は全字幕共通。プリセットを3種類用意する（白文字＋黒縁、黄文字＋黒縁、白文字＋半透明帯）。

## 9. BGM挿入と音量バランス

BGMファイルを入れるだけで「ループ・フェード・声の区間で自動的に下げる・全体の音量を揃える」まで自動で行い、ユーザーが触るのは「BGMの大きさ」スライダー1本だけ、を基本にする。

### 9.1 BGMの配置

- 対応形式：MP3、WAV、M4A（AAC）、OGG。全体をデコードしてAudioBufferとして保持する（数分の曲を想定）。
- 既定ではタイムラインの先頭から末尾まで1クリップを置き、`loop: true`、フェードイン1秒・フェードアウト2秒。
- ループのつなぎ目は50msのクロスフェードで処理する。
- 区間を指定して複数のBGMを並べることもできる（重なりは不可）。

### 9.2 ダッキング

- 発話区間（7.2のVAD結果）をタイムライン時刻に変換し、0.5秒未満の隙間は結合する。
- VADが使えない場合（ゲームモードで声がない場合）は、元音声の短期ラウドネスがベースライン+3dBを超える区間を代わりに使う。
- 発話区間ではBGMを `amountDb`（既定12dB）下げる。立ち下がり（attack）150ms、保持（hold）300ms、戻り（release）500ms。
- ゲインカーブは保存せず、再生・書き出しのたびに導出する（`core/audio/ducking.ts` の純粋関数）。
- プレビューでは再生開始時とシーク時に、カーブを `setValueAtTime` / `linearRampToValueAtTime` でBGMのGainNodeにスケジュールする。
- タイムラインのBGMトラック上に、このカーブを線で表示する。

### 9.3 ラウドネスと音量バランス

- ITU-R BS.1770に基づく積分ラウドネス（LUFS）をWorker内で計算する（Kウェイティング＋ゲーティング、自前実装）。
- 元音声：残っている区間のLUFSを測り、プリセットの基準値に合うゲインを自動で掛ける。
- BGM：元音声のラウドネスに対して、プリセットごとの差を基準に置く。そこに `bgmOffsetDb` を加える。

| プリセット | BGMの基準（元音声比） | 想定                             |
| ---------- | --------------------- | -------------------------------- |
| トーク     | −20 LU                | 解説・雑談、声を最優先           |
| ゲーム実況 | −15 LU                | 実況あり、ゲーム音もある         |
| BGM主体    | −6 LU                 | 声なしのプレイ動画、モンタージュ |

- 最終ミックス：全体を `targetLufs`（既定 −14 LUFS）に正規化し、最後にルックアヘッド5msのリミッターでトゥルーピークを −1 dBTP 以下に抑える。
- 上記の基準値は初期値であり、実素材で聴いて調整する。
- プレビューでも同じゲイン値を使う。ただしリミッターはプレビューでは簡易版（DynamicsCompressorNode）でよい。

## 10. 書き出し

書き出しはexport.workerで「映像フレームのデコード → OffscreenCanvasで字幕を合成 → エンコード」を行い、音声は別系統でミックスしてMP4にまとめる。保存先へは逐次書き込み、出力ファイル全体をメモリに持たない。

### 10.1 出力設定

| 項目           | 選択肢                                           | 既定       |
| -------------- | ------------------------------------------------ | ---------- |
| 解像度         | 素材と同じ / 1080p / 720p                        | 1080p      |
| フレームレート | 素材と同じ / 60 / 30                             | 素材と同じ |
| 画質           | 高画質 / 標準 / 軽量（ビットレートのプリセット） | 標準       |
| 字幕           | 焼き込む / 焼き込まない                          | 焼き込む   |
| 映像コーデック | H.264                                            | H.264      |
| 音声コーデック | AAC（エンコード不可の環境ではOpus）              | AAC        |

コーデックの可否は書き出し前に `canEncode` 系のAPIで確認し、不可なら理由を表示する。

### 10.2 処理の流れ

1. 保存先を `showSaveFilePicker` で先に選ばせ、書き込みストリームを開く（非対応時はメモリ上に作ってダウンロード。この場合は2GB程度を上限と警告する）。
2. 映像：クリップ順に、ソース区間のフレームをデコードしてOffscreenCanvasに描く。素材と出力の解像度が違えばレターボックスで収める。
3. 字幕：プレビューと同じ `renderSubtitles(ctx, items, t, style, w, h)` を呼ぶ。フォントはWorker内でも `FontFace` で読み込み、読み込み完了を待ってから開始する。
4. フレームレート変換：出力のフレーム時刻ごとに直近のソースフレームを使う（補間はしない）。
5. 音声：元音声のクリップとBGMを、ゲインとダッキングカーブを掛けながら1秒程度のチャンクで48kHzステレオにミックスし、正規化とリミッターを通してエンコーダへ渡す。正規化に使う全体LUFSは、事前に1パス目で計算しておく。
6. 映像と音声のタイムスタンプは、どちらもタイムライン時刻から計算する（A/Vずれを防ぐため、クリップ境界ごとに再計算する）。

- 進捗（％と残り時間の目安）を表示し、キャンセルできる。
- 書き出し中は「このタブを開いたままにしてください」と目立つ表示を出し、タブを閉じようとしたら確認ダイアログを出す（beforeunload）。

### 10.3 書き出しの安定性（背圧・バックグラウンド）

長時間の書き出しで詰まるのは「デコードがエンコードより速く、フレームが溜まり続ける」場合と「タブが裏に回って処理が間引かれる」場合なので、どちらも構造で防ぐ。

- **背圧**：フレームはMediabunnyの非同期イテレーションで1枚ずつ取り出し、エンコーダの `encodeQueueSize` が上限（目安30）を下回るまでawaitしてから次を取り出す。WebCodecsのデコーダを直接扱う場合は `decodeQueueSize` も同様に制限する。
- **待ち方**：待機はタイマーのポーリングではなく、エンコーダ／デコーダの `dequeue` イベントやPromiseで行う。タイマーはバックグラウンドで間引かれるため、ループの駆動に使わない。
- **非同期コールバックに頼らない**：デコーダの `output` コールバック内でawaitしても背圧にはならない（デコーダは待たずに次を出力する）。待機は必ずフレームを取り出す側のループに置く。
- **スリープ防止**：書き出し中は Screen Wake Lock API で画面の消灯を防ぎ、完了・キャンセル・エラー時に必ず解放する。
- **リソースの集中**：書き出し中はプレビュー再生とタイムラインの再描画を止め、文字起こしや再解析は開始させない。
- **採用しないもの**：無音オーディオを再生してスロットリングを避けるような裏技は使わない。ブラウザの仕様変更で効かなくなるうえ、挙動が読めなくなるため。

### 10.4 SRT書き出し

- 字幕をタイムライン時刻に変換し、カットで消えた字幕は除いてSRTを出力する。
- 文字コードはUTF-8（BOMなし）。

## 11. UI/UX

画面は「ヘッダー・左パネル・プレビュー・タイムライン」の4領域で、一般的な編集ソフトと同じ配置にする。初心者向けに、上部に作業の流れを示すステップ表示を置くが、どのステップの機能にもいつでも戻れる。

### 11.1 画面構成

- **ヘッダー**：プロジェクト名、保存状態の表示（保存中／保存済み／保存失敗）、Undo/Redo、解析の進捗、「書き出し」ボタン。
- **ステップ表示**：①読み込み → ②カット → ③字幕 → ④BGM → ⑤書き出し。クリックで左パネルの内容が切り替わる。
- **左パネル**（ステップに応じて切り替え）：素材一覧／自動カット候補と各種スライダー／文字起こしパネルと字幕スタイル／BGMと音量プリセット。
- **プレビュー**：中央。再生ボタン、現在時刻／全体の長さ、プレビュー解像度。
- **タイムライン**：下部。3トラック、ズームスライダー、スナップのオン／オフ。

### 11.2 初回体験

1. 起動すると空の画面に大きなドロップ領域と「ゲーム録画」「トーク動画」のモード選択を出す。
2. 動画を入れると解析が自動で始まり、終わると②カットのステップに自動で移り、候補を表示する。
3. 各ステップの左パネル上部に、そのステップでやることを1行で表示する。

## 12. 非機能要件・制約・エラー処理

想定する最大入力は「2時間・1080p60」、最大出力は「30分」とし、その範囲でメモリを2GB以内に抑える。性能目標は一般的なゲーミングPC（独立GPUあり）を基準とし、実測して見直す。

### 12.1 性能目標（初期値）

| 項目                                       | 目標                          |
| ------------------------------------------ | ----------------------------- |
| 1時間の録画の音声解析（エンベロープ＋VAD） | 3分以内                       |
| タイムライン操作（500クリップ）            | 60fps                         |
| 分割・削除などの編集操作の反映             | 50ms以内                      |
| プレビューのカット境界での途切れ           | 100ms以内                     |
| 書き出し（1080p30・10分）                  | 実時間以下（10分以内）        |
| メインスレッドの長時間ブロック             | 100ms以上のブロックを作らない |

### 12.2 保存と再開

- プロジェクトJSONは変更のたびに1秒デバウンスでIndexedDBに自動保存する。
- 再開時はIndexedDBのファイルハンドルから素材を開き直す。権限の再要求が必要ならボタンを出す。
- ハンドルが無効な場合は、ユーザーにファイルを選び直してもらい、fingerprintで同一性を確認する（不一致なら警告）。
- プロジェクト一覧画面で、作成・開く・名前変更・削除ができる。
- プロジェクトJSONのエクスポート／インポート（`.json`）を用意する（素材は含まない）。

### 12.3 エラー処理

| 状況                           | 対応                                                                         |
| ------------------------------ | ---------------------------------------------------------------------------- |
| 非対応ブラウザ・機能不足       | 起動時に不足機能を列挙して警告。編集は続行可能、使えない機能はボタンを無効化 |
| デコードできないコーデック     | 読み込み時に拒否し、OBSなどでH.264のMP4に変換する方法を案内                  |
| WebGPUが使えない               | 音声認識をWASMで実行し、遅くなる旨を表示                                     |
| モデルのダウンロード失敗       | 再試行ボタン。部分的にキャッシュされたファイルは破棄                         |
| OPFSの容量不足                 | 解析キャッシュの削除を促す（設定画面にキャッシュ使用量と削除ボタン）         |
| メモリ不足・Workerのクラッシュ | 処理を中断して通知。プロジェクトは自動保存済みの状態に戻す                   |
| 書き出しの失敗                 | 途中ファイルを削除し、失敗したタイムライン時刻をログに残して表示             |

### 12.4 その他

- UIは日本語のみ。文言は1ファイルにまとめ、将来の多言語化に備える。
- 外部への送信はモデルのダウンロードのみ。アクセス解析は入れない。
- 主要なボタンにはツールチップとキーボードショートカットの表記を付ける。

### 12.5 メモリとリソース管理

大きなメモリの多くはJSのGCが回収するまで待てないもの（デコード済みフレーム、WASMのヒープ、GPUバッファ）なので、解放はすべて明示的に行う。

- `VideoFrame` と `AudioData` は使い終わった時点で必ず `close()` する。途中で例外が出ても漏れないよう `try / finally` で囲む。
- Worker間・メインスレッドとのバイナリの受け渡しは、`ArrayBuffer` をTransferableとして移譲し、コピーしない。
- 音声認識やVADのモデル（ONNXセッション、Transformers.jsのパイプライン）は、使わなくなったら明示的に解放する。モデルを切り替えるときは、古いものを解放してから新しいものを読み込む。
- OPFSへの大きな読み書き（`pcm16k` など）はWorker内で `FileSystemSyncAccessHandle` を使い、チャンク単位で行う。
- 文字起こしと書き出しは同時に実行しない。重い処理はジョブキューで管理し、音声解析だけは編集中のバックグラウンド実行を許可する。
- 開発中は、長時間の書き出しや文字起こしの間のメモリ使用量をDevToolsで記録し、増え続けないことを確認する。

### 12.6 処理のキャンセルと後片付け

- 重い処理にはすべて `AbortSignal` を渡し、Worker内のループはチャンクの区切りごとに中断を確認する。
- 片付けは `finally` に集約し、正常終了・エラー・キャンセルのどの経路でも同じ処理を通す：デコーダ／エンコーダの `close()`、保持中のフレームの解放、一時ファイル（OPFSの作業ファイル、書きかけの出力ファイル）の削除、Wake Lockの解放。
- キャンセルした処理の途中結果はプロジェクト状態に反映しない。ただし文字起こしの処理済みセグメントはキャッシュに残し、再実行時に再利用してよい。

## 13. 実装フェーズとClaude Codeへの指示

実装は6フェーズに分け、各フェーズの受け入れ基準をすべて満たしてから次に進む。最初に「字幕もBGMもない、切って書き出すだけ」を通し、メディア入出力の難所を先に潰す。

### 13.1 Claude Codeへの共通指示

- この設計書を `docs/DESIGN.md` としてリポジトリに置き、`CLAUDE.md` から参照すること。
- 型と純粋関数（`src/core/`）を先に書き、Vitestでテストしてから、その上にUIを作ること。
- Mediabunny、Transformers.js、onnxruntime-web、Silero VADのAPIは、この設計書の記述ではなく最新の公式ドキュメントで確認すること。
- 重い処理（デコード、解析、音声認識、書き出し）はメインスレッドで行わないこと。12.5（メモリとリソース管理）と12.6（キャンセルと後片付け）のルールはP1の時点から守ること。
- スコープ外の機能は実装せず、思いついたものは `docs/TODO.md` に書き残すこと。
- 設計書と異なる判断をした場合は、`docs/DECISIONS.md` に日付・理由とともに記録すること。
- テスト用の素材はリポジトリに含めず、`scripts/make-fixtures.sh` でffmpegを使って生成すること（テストパターン映像、サイン波と無音を交互に並べた音声、2音声トラックのMP4など）。
- 1フェーズを複数のコミットに分け、各コミットで `npm run build`、`npm run lint`、`npm test` が通ること。

## 14. 将来拡張

MVPのデータモデルは以下を後から足せるようにしておく。特に、自動処理はすべて `Suggestion` か字幕トラックに書き込む形なので、新しい検出器を足しても編集UIは変えずに済む。

| 拡張                           | 概要                                                                                                                                           | MVPでの備え                                              |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 映像のシーン検出               | 縮小フレームの差分で場面転換を検出し、カット点を吸着させる                                                                                     | 候補生成を検出器ごとのモジュールに分けておく             |
| フィラー語カット・テキスト編集 | 「えー」「あのー」の検出、文字起こしの文字を消すとその区間がカットされる                                                                       | 単語タイムスタンプを保存しておく                         |
| Geminiによるハイライト選別     | ユーザー自身のAPIキー（BYOK）で、候補区間の縮小版を送り面白さを順位付け                                                                        | `Suggestion.score` を外部から上書きできるようにする      |
| VOICEVOXの読み上げ             | ローカルのVOICEVOXエンジンを呼び、字幕テキストから音声を生成して音声トラックに置く。VOICEVOX側のCORS許可設定と、クレジット表記の自動挿入が必要 | 字幕アイテムに任意の音声を紐付けられる余地を残す         |
| 縦動画・ショート向け           | 9:16の出力と切り抜き位置の指定                                                                                                                 | 出力解像度をプロジェクト設定に持つ                       |
| Google Drive連携               | 録画の読み込みと書き出し先                                                                                                                     | 素材の入出力を抽象化しておく                             |
| デスクトップ版                 | Tauriで包み、重い処理をネイティブのffmpegとfaster-whisperに置き換える                                                                          | 解析・認識・書き出しをWorkerのインターフェースの裏に隠す |
